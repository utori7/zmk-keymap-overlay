# ZMK 側の変更 — 作業手順

オーバーレイをキーボードのレイヤーに追従させるための作業。
**GitHub のウェブ画面とファイルのコピーだけで完結する。**
コマンド入力は要らない。

所要 20〜30 分（うち待ち時間 10 分ほど）。

---

## これは何をする作業か

キーボードのレイヤー切替は、キーボードの中だけで完結していて PC には何も届かない。
だから PC 側は「いま何レイヤーか」を知りようがない。

そこで**レイヤーに入ったとき、こっそり F13〜F16 を一緒に押しっぱなしにする**ように
キーボードを書き換える。PC 側はそれを見てオーバーレイを出す。

F13〜F16 は普通のキーボードには無いキーで、他のアプリにも届かないようにしてあるので、
何かが誤作動することはない。

変更するのは**キーボードの設定ファイル 2 か所だけ**。
うまくいかなければ元に戻せる（[元に戻す](#元に戻す)を参照）。

---

## 全体の流れ

```
0. 今の firmware を保存しておく   ← 戻すときに使う。必ず先に
1. GitHub でファイルを 2 つ直す
2. GitHub が自動でビルドする      ← 待つだけ
3. できた firmware を右手側に書き込む
4. 確認する
```

**前提**: リポジトリ `utori7/zmk-config-Pyuron` の **`paw3220` ブランチ**。

---

## 0. 今の firmware を保存しておく（重要・先にやる）

失敗したときに書き戻すためのもの。これをやっておけば必ず元に戻せる。

1. ブラウザで `https://github.com/utori7/zmk-config-Pyuron` を開く
2. 上の方の **Actions** タブをクリック
3. 一覧のいちばん上あたりにある、**緑のチェックマーク ✅ が付いた**行をクリック
4. ページをいちばん下までスクロールする
5. **Artifacts** という欄の **firmware** をクリックすると zip がダウンロードされる
6. この zip を、後で分かる場所に置いておく（例: デスクトップに `firmware-backup.zip`）

> 赤い × が付いている行はビルドが失敗したもの。緑のものを選ぶこと。

---

## 1. GitHub でファイルを直す

### 1-1. `layer-signal.dtsi` を置く

1. リポジトリのトップページで、**`config`** フォルダをクリックして中に入る
   - ここで中に入っておくのが大事。トップのままだと置き場所を間違える
2. 右上の **Add file** ▾ → **Upload files** をクリック
3. 渡した `layer-signal.dtsi` を、点線の枠の中にドラッグして放り込む
4. 下の **Commit changes** ボタンを押す
   - その上のラジオボタンは **Commit directly to the `paw3220` branch** のままでよい

画面が戻ったら、`config` フォルダの中に `layer-signal.dtsi` が並んでいるはず。

### 1-2. `Pyuron.keymap` を 2 か所直す

1. `config` フォルダの中の **`Pyuron.keymap`** をクリック
2. 右上のえんぴつマーク ✏️（Edit this file）をクリック

これで文字を直せる状態になる。

#### 直す場所 その 1 — 4 行を追加する

`Ctrl+F` でファイル内を検索して、この行を探す（15 行目あたり）。

```
#define L_SYS    5
```

その行のすぐ下に**空行が 1 行**あるはず。その空行のところに、以下を貼り付ける。

```
/* Layer-entry signal keys for the PC-side keymap overlay.
 * Must come after the L_* defines above.
 */
#include "layer-signal.dtsi"
```

貼り付けたあと、こう見えていれば正しい。

```
#define L_MOUSE  4   // click only           - trackball auto ON
#define L_SYS    5   // bluetooth / boot     - Kana hold  (pos 38)

/* Layer-entry signal keys for the PC-side keymap overlay.
 * Must come after the L_* defines above.
 */
#include "layer-signal.dtsi"

/* ===== JIS (Japanese 106/109) symbol aliases =====
```

#### 直す場所 その 2 — 1 行を置き換える

`Ctrl+F` でこの行を探す（170 行目あたり、`default_layer` の中の最後の行）。

```
&htp LSHFT TAB  &kp LCTRL      &lt L_SYM INT5  &lt L_NAV SPACE
```

**この 1 行をまるごと選択して**、以下で置き換える（1 行のまま。途中で改行しない）。

```
&htp LSHFT TAB  &kp LCTRL      &lt_sym L_SYM INT5  &lt_nav L_NAV SPACE                                    &kp BACKSPACE   &lt_func L_FUNC ENTER   &lt_sys L_SYS INT4   &htp DEL F10
```

やっていることは、`&lt` を 4 つとも `&lt_sym` / `&lt_nav` / `&lt_func` / `&lt_sys` に
変えているだけ。うしろの引数はまったく変えていない。

> **これ以外の行は触らないこと。** 特に `sym_layer` や `nav_layer` の中は
> 一切変更しない。

#### 保存する

1. 右上の **Commit changes...** ボタンを押す
2. メッセージ欄はそのままでよい（分かりやすくするなら `Add layer signal keys`）
3. **Commit directly to the `paw3220` branch** を選んだまま **Commit changes**

---

## 2. GitHub がビルドするのを待つ

commit した瞬間に、GitHub が自動でファームウェアを作り始める。

1. **Actions** タブを開く
2. いちばん上の行が、いま自分が commit したもの。黄色い丸 🟡 が回っている＝ビルド中
3. **5〜10 分ほど待つ**

### 緑のチェック ✅ になったら

成功。次へ進む。

### 赤い × になったら

**書き間違いがある。** ここで止まってくれるので、キーボードは無事なまま。

その行をクリック → 赤い × の付いたジョブをクリックすると、エラーの内容が見られる。
その画面をスクリーンショットで送ってもらえれば直せる。

やり直したい場合は [元に戻す](#元に戻す)へ。

---

## 3. 右手側に書き込む

**書き込むのは右手側だけでよい。** キーマップは右手側が持っているため、
左手側はさわらなくていい。

### 3-1. ファームウェアを取り出す

1. Actions タブ → いま成功した緑 ✅ の行をクリック
2. いちばん下の **Artifacts** → **firmware** をクリックして zip をダウンロード
3. zip を展開する。中に `.uf2` ファイルがいくつか入っている
4. **名前が `Pyuron_R` で始まるファイル**を使う（例: `Pyuron_R-xiao_ble-zmk.uf2`）
   - `Pyuron_L` は左手側。今回は使わない
   - `settings_reset` は使わない

### 3-2. 書き込む

1. **右手側**のキーボードを USB ケーブルで PC につなぐ
2. 右手側の基板にある**小さなリセットボタンを、素早く 2 回押す**（ダブルクリックの要領）
3. PC に **`XIAO-SENSE`** という名前のドライブ（USB メモリのようなもの）が現れる
4. さきほどの `Pyuron_R...uf2` を、そのドライブに**ドラッグしてコピー**する
5. コピーが終わるとドライブが勝手に消える。**これで書き込み完了**

> ドライブが現れないときは、2 回押すのが遅すぎる/速すぎる可能性がある。間隔を変えて再挑戦する。

> **注意**: L5 レイヤーにある `BOOT` キーは**左手側**を書き込みモードにするもの。
> 今回は右手側なので使えない。物理のリセットボタンを使うこと。

---

## 4. 確認する

オーバーレイより先に、**キーボードとして普通に使えるか**を確かめる。
この順番で見ること。

| # | やること | 期待する結果 |
|---|---|---|
| 1 | 親指キーを**軽く叩く** | 英数 / Space / Enter / かな がそれぞれ出る |
| 2 | **Space を押しながら**素早く `h j k l` を打つ | カーソルが動く（文字が出たら問題あり） |
| 3 | 英数を**押しっぱなし**にして数字の行を打つ | 数字・記号が出る |
| 4 | 親指を離す | 普通の文字入力に戻る |
| 5 | オーバーレイを起動して親指を押しっぱなし | 押している間だけ表示され、離すと消える |

**2 が今回いちばん危ないところ。** ここで文字が出てしまう場合は、
レイヤーの切り替わりがわずかに遅れている。直せるので症状を教えてほしい。

5 まで通れば完成。

---

## 元に戻す

### キーボードを元に戻す

手順 0 で保存した `firmware-backup.zip` を展開し、
`Pyuron_R` で始まる `.uf2` を、[3-2](#3-2-書き込む) と同じ手順で書き込む。
これで完全に元の状態に戻る。

### GitHub の変更を元に戻す

1. リポジトリの **Code** タブ → 右側の **Commits**（時計のようなアイコン）をクリック
2. 自分が行った commit を探してクリック
3. 右上の **⋯** → **Revert** を選ぶ

または、`Pyuron.keymap` を開いて **History** から前のバージョンを見ながら
手で戻してもよい。`layer-signal.dtsi` は残っていても害はない
（`#include` の行を消せば使われなくなる）。

## PC 側の設定

キーボードを書き込んだら、オーバーレイの `config.json` に対応表を書く。
設定例は [../data/config.zmk.example.json](../data/config.zmk.example.json) がそのまま使える。

```json
"zmk": { "signalKeys": { "1": "F13", "2": "F14", "3": "F15", "5": "F16" } }
```

書き込む前でも、PC 側だけなら確かめられる。

```bash
dotnet run --project tools/HotkeyProbe -- --hold F13 3000
```

# 背景（技術メモ）

ここから下は、あとで中身を追いたくなったとき用。作業には要らない。

## 合図キーの割り当て

| レイヤー | 入口 | 合図キー |
|---|---|---|
| L1 SYM | pos 34 hold | F13 |
| L2 NAV | pos 35 hold | F14 |
| L3 FUNC | pos 37 hold | F15 |
| L4 MOUSE | （自動） | 対応不可 |
| L5 SYS | pos 38 hold | F16 |

L4 はトラックボール操作で `zip_mouse_temp_layer` が自動 ON にするもので、
キー押下を経由しないためマクロを差し込む場所が無い。

PC 側は `RegisterHotKey` で合図キーを予約する。予約したキーは
フォーカスのあるアプリに届かなくなるため、F13〜が漏れることはない
（[../DESIGN.md](../DESIGN.md) の「抑止の検証結果」で実測済み）。

## 前提にしているキーマップ

| | |
|---|---|
| リポジトリ | `utori7/zmk-config-Pyuron` |
| ブランチ | `paw3220`（リポジトリの既定ブランチ） |
| コミット | `6ec4af4` "Update key bindings in Pyuron.keymap" (2026-08-15) |

このコミットに対して `git apply --check` が通ることを確認済み。
コマンドが使えるなら `zmk/Pyuron.keymap.patch` を `git apply` してもよい。

既存キーマップに F13〜F24 の使用は無く、追加するラベル名
（`lt_sym` / `mo_sig_*` / `SIG_*`）とも衝突しないことを確認済み。

## なぜこの書き方なのか

**ZMK の hold-tap は param1 を hold 側、param2 を tap 側へ固定で渡す。**
`#binding-cells` は必ず `<2>` で、hold 側のビヘイビアは引数をちょうど 1 つ取る必要がある。

そのため合図キーはマクロ側に焼き込み、レイヤー番号だけを引数で渡す形にしてある。
おかげで呼び出し方は素の `&lt` と同じ並びのままになる。

```
&lt     L_SYM INT5      ->      &lt_sym L_SYM INT5
```

`wait-ms = <0>` / `tap-ms = <0>` は必須。既定のままだとバインディングの間に 100ms 入り、
レイヤー有効化がそのぶん遅れて、レイヤーに入った直後の打鍵が下のレイヤーに落ちる。
`&mo` を合図キーより先に置いているのも同じ理由。

`flavor` と `tapping-term-ms` は組み込みの `&lt` と同じ値（`tap-preferred` / 200ms）。
最初の版はここを `hold-preferred` にしていたが、ZMK のソース（`app/dts/behaviors/layer_tap.dtsi`）で
確かめると組み込みは `tap-preferred` だった（2026-09-16 に修正）。`hold-preferred` だと、親指キーを
押したまま次の文字を素早く打ったときにレイヤーへ入りやすい。
打鍵感を変えないため。

## うまくいかなかったときの手

| 症状 | 対処 |
|---|---|
| 確認 2 が再現する（レイヤー直後の打鍵が落ちる） | `tapping-term-ms` を伸ばして hold の確定を遅らせる |
| それでも直らない | 案 B（ファームから raw HID でレイヤー状態を通知）に切り替える |
| 打鍵感が変わった | `flavor` と `tapping-term-ms` が組み込みの `&lt` と同じか確認する |

### 案 B が現実的になっている点

この config は既に `CONFIG_ZMK_STUDIO=y` で ZMK Studio を有効にしている。
vendor HID のパイプが既に通っている構成なので、案 B に移る下地はある。
キーマップを一切汚さずに済み、L4 MOUSE も取れるようになる。
